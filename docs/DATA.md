# 数据结构与计算

SQLite 单用户账本，每个 UUID 都由服务器生成。

| 表 | 用途 |
|---|---|
| accounts | 独立账户 id、名称、类型、账单本币 |
| transactions | 稳定 id、account_id、交易及入账日期、本币整数分、原币整数分和币种、明确类型、posted/pending、分类、备注、manual 标志、精确指纹和出现次数 |
| files | 原始名称、账户、SHA-256、私人文件 id、格式、可选明确覆盖范围；原件本身放在私人 files/id |
| sources | 多对多 transaction_id/file_id + 文本页码／行号，更新不覆盖原来源 |
| aliases | 正式记录更新后的新指纹指向原稳定 id，使后续重叠导入仍匹配 |
| categories | 大类、二级列表和稳定颜色 |
| rules | 完全相同描述的未来分类／类型规则，不覆盖现有记录 |
| sessions | 服务端随机会话 ID 和过期时间；退出或重设密码会撤销 |

金额保留整数分，输入由 Decimal 验证；前端只把最终展示转换成两位小数。消费 = 当前时间／账户／本币筛选下 type=expense 且 status=posted 的 amount 总和。收入同理。结余=收入−消费。消费分类和子分类都来自同样的记录，不使用维护的累计字段。

分类占比 = 该大类消费／当前筛选范围内全部消费，保留所有扇区及列表，只有实际占比≥3% 才绘制图上文字和引导线。空消费避免除零。年度不跨本币合计。

XML/CSV/PDF 解析在本实例执行，无外部连接。Excel 出站文本以 string 保存，避免商户描述或备注变成执行公式。年度导出仅由后端维护的公式单元格是公式，不把导出报表当入站银行原件。

导入数据库事务使用 BEGIN IMMEDIATE；确认阶段重新查去重状态，防止两次预览并发提交造成重复。唯一约束提供最终保护。保留来源与正式匹配的多个指纹。全部金额／日期冲突明确失败或确认，不猜测。

CSV／XLSX 列映射、分隔符及明确选择的日期格式保存在私人预览元数据中，确认阶段按同一设置重新解析。别名和映射不改写来源文件，行号仍对应原件。未确认类型只存在于预览，不计入统计、不能提交到交易表；必须选择明确类型或跳过。标准表头与映射文件采用同样的稳定 ID 和去重规则。
